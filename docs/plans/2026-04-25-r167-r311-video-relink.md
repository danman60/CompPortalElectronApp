```sql

SET
  performance_video_url = v.perf,
  judge1_video_url = v.j1,
  judge2_video_url = v.j2,
```

- Operator believes the linkage was "cleaned up" — but no code/migration trace was found in transcripts for today. Either the bulk update was an automated trigger (e.g., a no-op sweep that touched updated_at across rows but didn't actually NULL the URLs) — meaning the URLs were ALREADY NULL when that sweep ran.
- If URLs were never set: the upload pipeline must have stalled for R167+ yesterday despite having the encoded mp4s on disk. Yesterday's transcript (line 6062–6094) shows R160's photos blocked behind R116-R145 in the upload queue around 12:25 EDT yesterday — entirely plausible the video upload queue ALSO stalled in this range and never recovered.

If yes, the URLs got nulled later. If no, the upload pipeline never finished for these. The fact that encoded mp4s exist proves the encode pipeline finished; the upload pipeline is the suspect.
